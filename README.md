# Lubi Web · 原插件运行版

此项目以 `obsidian_task_kanban/插件源码/lubi` 的 **1.8.0 / schema v14** 为基准。不是重新画一套类似页面：原插件的业务、视图、表单、交互和全部样式直接运行；仅把 Obsidian 宿主 API 替换为浏览器宿主与独立 SQLite 虚拟 Vault。

`packages/plugin-runtime/src` 的 71 份源文件／样式有逐文件 SHA-256 校验。宿主适配在 `apps/web/src/host`，后端在 `apps/api/src`。历史阶段文档集中在 [`docs/archive/`](docs/archive/README.md)，不代表本版状态；当前说明入口见 [文档索引](docs/README.md)。

## Windows 直接使用

双击 **`启动 Lubi.cmd`**。需要 Node.js **24+**。

- 首次按锁文件安装依赖，生成独有的 `.env.local` 访问密码，再构建并启动。
- 浏览器自动打开 `http://127.0.0.1:3000`；密码显示在该启动窗口，也保存在 `.env.local`。请勿分享或提交它。
- 保持启动窗口运行；Ctrl+C 停止。数据不随关闭浏览器或服务重启丢失。
- 不占用已在使用的端口；如有冲突，在 `.env.local` 设置其他 `PORT`，再启动。

终端等价操作：

```sh
npm ci
npm run setup
npm run build
npm start
```

开发模式：`npm run dev` 同时管理 API 和 Vite，默认访问 `http://127.0.0.1:5173`。独立调试仍可运行 `npm run dev:api` / `npm run dev:web`。浏览器始终使用相对 `/api` 地址，不连接浏览器自己的 localhost 后端。

## 功能与入口

- **计划**：列表／日历／甘特图 × 日／周／月；共享日期、范围导航、项目／旧父任务分组、未安排、排序、拖动／伸缩与撤销。
- **任务与实际**：原统一任务表单、轻量编辑、地点、备注、预计、重复／跨度、逐次完成／跳过、实际用时与预计快照、跨午夜拆分、待确认处理、支出。完成／验收不会凭空生成实际记录。
- **后台任务**：原 Agent 手动运行→待审核→验收／返工；后台墙钟与本人投入分开。和原插件一样，这些按钮不真正启动或控制 Agent。
- **回顾**：原周／月／年统计、趋势、分类／事项／支出明细及图表／表格。
- **更多 → 工作复盘与整理**：预算与投入、成果／验收、周复盘与行动、待整理／批量改期／拆分、可暂停和重启续接的实时计时、隔离数据恢复。
- **命令**：Ctrl / ⌘ + P 可搜索并执行原插件注册的 13 个命令；也可从 Web 设置打开命令面板，不丢失下层表单草稿。
- **顶部**：原 JSON 任务导入、AI 草稿确认创建、统一新建和原键盘快捷键／悬停提示／明暗与窄屏布局。
- **更多 → 设置**：保留原插件设置，增加 Web 主题、文件查看／编辑、Web 文件备份／隔离恢复、服务端加密密钥库及退出登录。

## 数据边界：不碰原 Vault

这个 Web 服务**不会打开、扫描或同步原 Obsidian Vault**。虚拟文件只存在自己的数据库中，不是服务器任意文件访问接口。

- 默认数据库：项目根 `data/lubi.db`。配置按系统环境变量 > `.env.local` > `.env` 的优先级读取。
- 旧版默认 `apps/api/data/lubi.db` 若仍存在会被识别保留；有两个候选库时拒绝猜测，请明确设置绝对 `LUBI_DB_PATH`。
- 检测到旧 Web 表且新 Vault 为空时，登录后明确确认升级；转换有事务备份，保留旧表。完整模式启用后，旧写 API 被冻结，旧只读导出仍保留。
- v14 JSON 和 Markdown 作为原始文本保存；未知字段及日记非记录章节不被简化投影丢弃。
- 文件和设置写入带版本检查。并发修改会报冲突而不是覆盖；错误／重新登录保留表单草稿。原始文件编辑器还会保留未保存文本并提示离开。
- 数据恢复默认写到**新隔离目录**，不覆盖活动文件。原插件完整导出 `lubi-data v1` 在「工作复盘与整理 → 数据恢复」导入；检查恢复说明后，可在原设置里切换任务文件和日记目录。
- 虚拟路径为相对路径，不接受绝对路径、`..`、隐藏路径或系统盘路径。单文件最多 4MiB，Web 文件备份恢复最多 25MiB；更大工作区使用下述 SQLite 备份。

## 三类备份不要混淆

| 入口 | 内容 | 恢复方式 |
|---|---|---|
| 更多 → 导出数据 JSON | 原 `lubi-data v1`，v14 TaskStore 与可解析记录；不含设置、密钥和日记其他正文 | 原「数据恢复」，新隔离目录 |
| 设置 → 下载 Web 文件备份 | 全部虚拟文本文件，包含日记其他正文；不含设置、密钥、删除历史 | 设置 → 恢复 Web 文件备份，校验后复制到新隔离目录 |
| `npm run backup` | SQLite 一致性在线备份：全部文件、设置、历史和加密密钥条目；本地密钥文件单独随备份保管 | `npm run restore:db -- 备份目录 [新目录]`，校验 SHA-256 与 SQLite 完整性，不替换现用库 |

SQLite 备份默认放在被 Git 忽略的 `backups/`。如果使用 `LUBI_SECRET_KEY` 环境密钥，备份不会导出它，必须另行安全保管。恢复命令只生成新目录，不改 `.env.local`；检查后再切换数据库和密钥路径。备份可能含个人数据及解密密钥，**不要提交、公开或分享**。

## AI 与命名密钥

AI 沿用原插件的兼容接口、模型获取、测试与确认草稿流程，只在主动操作时请求。

- 临时 API Key 仅在当前页面会话中使用，不写入设置／导出。
- 「钥匙串」在 Web 中对应**独立服务端密钥库**，不是 Obsidian 的系统钥匙串。命名密钥 AES-256-GCM 加密保存在 SQLite，主密钥默认在数据库旁的 `lubi-credentials.key`；请求时由后端解密，已有密钥不回传浏览器。
- 本机 Ollama 等服务需要显式设置 `LUBI_ALLOW_LOCAL_AI=1`，再重启；「本机」指后端所在电脑，不是另一部手机。
- 远程接口必须 HTTPS，禁止跳过证书、内网／特殊地址和任意 URL 代理；只有已保存的 AI origin 和公开版本查询可访问，不跟随跳转。
- 不填入真实密钥也能运行全部非 AI 功能。测试使用本地模拟接口，从不请求真实模型或使用真实凭据。

## 宿主差异（不是悄悄禁用功能）

原插件的核心功能与 UI 复用同一实现，但 Web 不是 Obsidian 本身：原 Vault／系统钥匙串／桌面文件安装器不与网页共享；日记与成果内链打开 Web 文件编辑器，导出触发浏览器下载。桌面插件更新仍应在 Obsidian 中操作，网页不会替用户改安装目录。自定义 Obsidian 主题、第三方插件和原生移动客户端不在网页宿主中运行。

真实 Obsidian 隔离客户端验证由 `npm run test:native` 单独执行（Windows 安装了 Obsidian 时）。它创建独立临时用户目录与合成 Vault，只复制软件运行归档，不复制真实配置、密钥或笔记；测试结束关闭自己的客户端并清理。

具体环境、通过数量、截图与尚未验证边界见 **`docs/验收记录.md`**。任何模拟／窄屏浏览器测试都不等于真实手机验收。

## 网络部署

默认仅监听回环地址，适合本机使用。服务提供同源生产静态页面、密码登录、HttpOnly / SameSite Cookie、持久化的哈希会话、登录限速、来源检查和 CSP。会话最长 24 小时，重启保留；改密码或退出使相应会话失效。

不要直接把 HTTP 服务暴露到公网。需要异机使用时配置你管理的 HTTPS 反向代理，再设置 `LUBI_HTTPS=1`；仅在代理会清洗转发头时使用 `LUBI_TRUST_PROXY=1`，可用 `LUBI_PUBLIC_URL` 指定启动时打开的 HTTPS 地址。此交付未发布到公网或创建 Release。Git 仓库只包含程序、测试和合成截图文档；本机 `.env.local`、数据库、备份及密钥不纳入提交。`.gitattributes` 固定源码换行，避免 Windows 自动换行转换破坏原插件的逐文件校验。
