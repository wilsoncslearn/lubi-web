# 原插件运行版：架构与数据安全

## 分层与不改动的边界

```
浏览器 / 原 Lubi 1.8.0 视图、服务、v14 领域逻辑、全部 CSS
    ↕ Obsidian API 浏览器宿主（DOM / 模态框 / 菜单 / 文件 / 设置 / 下载）
    ↕ 同源带 Cookie 的 /api/vault
Fastify / 文件与设置 CAS / 认证会话 / 受限 AI 代理
    ↕
独立 SQLite：虚拟文本文件 + 设置 + 版本 + 删除备份 + 旧表 + 加密密钥
```

- 原插件源文件由 `packages/plugin-runtime/UPSTREAM.json` 记录 SHA-256；`npm run check:upstream` 逐文件校验。修改位置是宿主或后端，而非重写／删减原业务。
- `scripts/prepare-upstream.mjs` 只合并样式、准备测试依赖和安装戳。原测试代码不改动，CLI 适配仅落在可重建的 `node_modules`。
- React 精简页面已从入口移除。旧领域模块／只读导出和回归用例仍保留，保证旧数据可追溯。
- 服务不加载真实 Obsidian 配置、Vault、系统钥匙串或其他桌面插件；无自动目录扫描导入。

## 写入协议

文件版本由 SQLite 单调递增。创建用预期版本 0，修改／删除用读取时版本，不接受「最后写入者自动胜出」。

浏览器为每个文件路径串行排队；每个 `TFile` 保留与其读出的文本对应的版本。后台 5 秒轮询更新缓存时，**不能把已经打开的旧编辑器升级到新版本**。旧编辑器保存时仍带旧版本并得到 409，其草稿保留，外部新内容不被覆盖。不会无提示重试覆盖。

设置也使用版本检查。保存失败不关闭表单；登录过期覆盖层不拆掉当前表单，重新登录后由用户重试。原始文件编辑器有未保存退出确认、Ctrl/Cmd-S、JSON 语法检查和草稿下载。

## 升级与恢复

旧项目／任务／记录只在明确调用升级入口后转换，事务中再次检查虚拟 Vault 为空。保存原表快照，并保留旧 SQL 表；v14 任务与 Markdown 使用原插件的格式化函数，跨午夜记录分日。升级后旧写接口拒绝修改，避免出现互相分叉的两套活动数据。

两种应用内 JSON 恢复只创建唯一的新目录。Web 全文件恢复在同一个事务中验证并写入；拒绝非法路径、重复路径、祖先冲突、超量文件／字节和恶意 JSON 结构。原文件不被删除、重命名或替换。

`backup.mjs` 使用 SQLite 在线备份 API，而不是只复制可能仍有 WAL 的主文件。`restore-db.mjs` 校验白名单文件、SHA-256 和数据库完整性，只能恢复到尚不存在的新目录；不改活动库和环境配置。

## 认证、网络与密钥

- 访问密码只配置在环境中或忽略提交的 `.env.local`；scrypt 校验。数据库保留密码版本及盐，不存登录密码明文。
- 随机会话令牌只以 SHA-256 哈希入库，24 小时到期、重启保持、退出撤销、改密码失效。Cookie 为 HttpOnly / SameSite=Strict，HTTPS 部署时另设 Secure。
- 认证按 Fastify 已匹配路由判断，不能用编码／重复路径绕过；有来源检查、登录限速、无缓存安全头及 CSP。
- 密钥内容 AES-256-GCM 加密，随机 12 字节 nonce，名称绑定 AAD。只列出名称，已有密钥不回传浏览器；失去已有主密钥时拒绝静默生成新钥匙。
- AI 代理仅允许保存配置中的接口 origin；HTTPS 校验证书，不跟随重定向，DNS 解析后钉住已验证的地址，禁止内网／环回／保留地址绕过。主动启用本机 AI 才放开相应限制。
- 请求最长 45 秒并限制回复大小，不是任意开放代理。公开版本查询也限定到 GitHub 仓库 API。

## 明确区别

浏览器下载、Web 文件编辑器、服务端命名密钥替代相应原生能力；不会调用桌面 `curl`、执行插件安装或写真实 Vault。浏览器窄屏与真正的 Obsidian 移动客户端不是同一个宿主。

测试与截图必须标明：原测试宿主参考、实际 Web 浏览器，还是实际 Obsidian Electron 客户端；不能把模拟宿主截图称作原生验收。
